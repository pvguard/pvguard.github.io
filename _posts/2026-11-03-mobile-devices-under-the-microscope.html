00. Antes de empezar

En esta oportunidad iniciaremos una exploración práctica del análisis de aplicaciones móviles desde la perspectiva de un evaluador de seguridad. Antes de profundizar en técnicas de análisis dinámico o de intentar identificar mecanismos de protección, es importante preparar un entorno controlado que permita observar el comportamiento de una aplicación en diferentes dispositivos y configuraciones.

El primer paso será reconocer el entorno de ejecución: qué sistema operativo utiliza el dispositivo, qué permisos tiene disponibles, qué restricciones de seguridad están activas y qué posibilidades ofrece un dispositivo con privilegios elevados. Para ello, trabajaremos con escenarios Android e iOS, utilizando tanto dispositivos físicos como entornos virtualizados.

01. Explorando Android rooteado — Samsung

Para comenzar, utilizaré un dispositivo Samsung SM-A225M con Android 12 y acceso root. Contar con un dispositivo rooteado permite realizar observaciones que normalmente están restringidas a una aplicación convencional, por ejemplo, revisar directorios internos, consultar información del sistema y analizar determinados comportamientos durante la ejecución.

Tip El acceso root debe entenderse como una condición especial del entorno de pruebas, no como un requisito para todas las evaluaciones. En un proyecto real conviene comparar el comportamiento de la aplicación en un dispositivo estándar y en otro con privilegios elevados.

1.1 Control remoto de pantalla con scrcpy

Para visualizar e interactuar con el dispositivo desde Kali Linux utilizaré scrcpy, una herramienta que permite mostrar y controlar un dispositivo Android conectado mediante ADB.

Descargué la versión v5.0.1 para Linux desde la sección de releases del proyecto.

Después de descargar el paquete, lo extraje y accedí al directorio correspondiente:

tar xf scrcpy-linux-x86_64-v5.0.1.tar.gz
cd scrcpy-linux-x86_64-v5.0.1

Con el dispositivo conectado y la depuración USB habilitada, ejecuté:

./scrcpy

La herramienta detectó el dispositivo Samsung y permitió visualizar su pantalla desde el equipo de análisis.

1.2 Verificación del acceso root

Antes de iniciar el análisis, comprobé que el dispositivo contara con privilegios root. Para ello utilicé una aplicación de verificación de root y confirmé que el acceso de superusuario estuviera disponible.

Esta comprobación permite validar que el entorno está preparado para las pruebas que requieran permisos elevados.

Importante Una aplicación de verificación es solo una referencia inicial: durante una evaluación también se debe comprobar el comportamiento real de los comandos y las restricciones del sistema.

1.3 Conexión mediante ADB y exploración del sistema

Con el dispositivo reconocido por ADB, ejecuté los siguientes comandos para iniciar una sesión de shell y comprobar el usuario efectivo:

adb devices
adb shell
su
whoami

Si el acceso root está correctamente concedido, el comando whoami debe devolver:

root

A continuación, realicé una exploración inicial de los directorios del sistema y de la ubicación donde Android almacena los datos de las aplicaciones:

ls
cd /data/data
ls

En esta ubicación pueden encontrarse directorios asociados a los paquetes instalados. El acceso y la visibilidad de su contenido dependerán de la versión de Android, los permisos y las políticas de seguridad del dispositivo.

2.1 Entorno seleccionado: Corellium

Para esta prueba de concepto utilizaré Corellium, una plataforma que permite trabajar con dispositivos móviles virtualizados. En este entorno prepararé instancias Android e iOS para observar su configuración y establecer conectividad desde Kali Linux.

La instancia Android utilizada aparece configurada con una versión de sistema indicada como 16.0.0 (Rooted). Esta característica permite trabajar en un escenario de laboratorio con privilegios elevados.

2.2 Conexión al dispositivo Android virtualizado

Para utilizar ADB desde el equipo de análisis, Corellium proporciona los parámetros de conexión del dispositivo. En este escenario, primero es necesario establecer la conexión VPN indicada por la plataforma.

Una vez descargado el archivo de configuración correspondiente, inicié OpenVPN:

sudo openvpn corelium.ovpn
Nota Utiliza el nombre exacto del archivo descargado. En las capturas se muestra corelium.ovpn; si tu archivo tiene otro nombre, reemplázalo en el comando.

Cuando OpenVPN informa que la secuencia de inicialización se completó, la interfaz VPN queda disponible. Después, utilicé el comando ADB proporcionado por Corellium:

adb connect 10.11.1.2:5001

La respuesta connected to 10.11.1.2:5001 confirma que ADB pudo establecer la conexión con el dispositivo virtualizado.

03. Explorando iOS — fase de pruebas

La evaluación no se limitará a Android. También incorporaré un entorno iOS para ampliar el alcance de las pruebas y observar las diferencias entre ambos sistemas operativos.

Para esta fase utilizaré una instancia virtualizada de iOS en Corellium. La plataforma permite acceder al dispositivo mediante los mecanismos de conexión que tenga habilitados la instancia y el proyecto.

3.1 Conectividad y acceso SSH

En el entorno mostrado, Corellium proporciona los datos de conexión SSH para acceder al dispositivo virtualizado. Antes de intentar conectarse, es necesario verificar que la VPN esté activa y que el servicio SSH de la instancia se encuentre disponible.

El ejemplo de conexión indicado por la plataforma es:

ssh root@10.11.1.1

En la captura se observa el establecimiento de la sesión SSH y la comprobación del usuario efectivo mediante:

whoami

La respuesta root indica que la sesión dispone de privilegios de superusuario en ese entorno de laboratorio.

Consideración técnica Que una instancia virtualizada permita acceso root o SSH no significa que todos los dispositivos iOS reales tengan esas capacidades. El resultado depende de la imagen, versión, configuración y características habilitadas en el entorno de pruebas.

04. ¿Qué buscaremos durante las pruebas?

Con los entornos preparados, el siguiente paso será ejecutar una aplicación de prueba y observar su comportamiento. El análisis podrá organizarse en las siguientes líneas de trabajo:

  1. Reconocimiento del entorno: versión del sistema operativo, modelo, arquitectura y configuración del dispositivo.
  2. Análisis de permisos: permisos solicitados por la aplicación y su justificación funcional.
  3. Inspección del almacenamiento: revisión autorizada de archivos, preferencias y datos locales generados por la aplicación.
  4. Análisis dinámico: observación del comportamiento de la aplicación durante su ejecución.
  5. Mecanismos de protección: evaluación controlada de las comprobaciones de root o jailbreak y de otras medidas de protección.
  6. Comunicaciones: observación del tráfico de red en un entorno de laboratorio y de acuerdo con el alcance autorizado.
  7. Comparación de plataformas: identificación de diferencias de comportamiento entre Android e iOS.
Objetivo El propósito no es únicamente conseguir acceso a un dispositivo rooteado o con jailbreak, sino comprender qué información expone la aplicación, qué controles implementa y cómo responde ante un entorno de análisis.

05. Consideraciones y alcance

Esta entrada documenta la preparación inicial de los dispositivos y la conectividad necesaria para comenzar las pruebas. Las siguientes etapas se desarrollarán de forma progresiva, utilizando aplicaciones de laboratorio y entornos controlados.

  • Utilizar únicamente aplicaciones propias, de prueba o con autorización expresa.
  • No acceder, extraer ni divulgar información personal de terceros.
  • Mantener aislado el entorno de laboratorio y proteger las credenciales de acceso.
  • Documentar los comandos, resultados y evidencias para facilitar la reproducibilidad.
  • Diferenciar los resultados obtenidos en dispositivos físicos de los obtenidos en entornos virtualizados.

Conclusión

La preparación de dispositivos Android rooteados y entornos iOS virtualizados constituye el punto de partida para una evaluación de seguridad móvil. Con herramientas como scrcpy, ADB, SSH, OpenVPN y Corellium, es posible construir un laboratorio que facilite la observación y el análisis del comportamiento de las aplicaciones.

En las próximas pruebas profundizaré en la interacción con una aplicación móvil de laboratorio, revisando sus mecanismos de protección y documentando los hallazgos desde la perspectiva de un pentester.
