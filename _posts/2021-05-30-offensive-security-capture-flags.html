Hola amigos en esta oportunidad vamos a tomar un desafio CTF conocido como born2root.

Bueno comencemos

Primeramente debemos conocer la ip de la maquina virtual en cual en este caso es 

#192.168.161.49




Es importante conocer también nuestra dirección IP del vpn que hemos activado para correr la maquina. En este caso es:  

#192.168.49.161 




Bueno entramos a la aplicación web con la IP victima que en este caso seria 192.168.161.49




Nos muestra un simple pagina HTML para ello procederemos dar un escaneo completo con nmap. para ello utilizamos este comando. 

#nmap -A -p- 192.168.161.49 

Si desean saber los conceptos de estos comandos les sugiero que echen un vistazo a blog donde especificamente hablo de nmap.

https://cyb3rgh0stsecurity.blogspot.com/2021/05/nmap-escanner-y-rastreo-de-puertos.html   




Las principales cosas que me saltan son ssh y http lo veremos mas adelante, nos dirigimos a interactuar con la pagina a ver que errores nos bota.

Bueno para ello voy a ejecutar gobuster para enumerar los directorios de la pagina o encontrar algunos archivos ocultos.






De nuestra salida de gobuster, no estamos viendo mucho. ¿Pero sabes que? Comprobaremos cada hallazgo de todos modos, ya que nunca se sabe lo que puede encontrar. Solo me enfocaré en los enlaces que devolvieron HTTP 200
 
Me da dos URL para verificar, http://192.168.161.49/manual/ y http://192.168.161.49/icons/. Navegaré a ambos usando Firefox y veré qué sucede.


Buscando entre las paginas encontré esto que me llamo la atención.

Tenemos una bonita clave privada! Genial, pero ¿de quién es la clave? Bueno, si volvemos a la página de inicio del sitio, había una lista de nombres en la sección Acerca de nosotros, así como una dirección de correo electrónico en Contáctenos. Me arriesgaría a adivinar que los nombres de usuario de cada persona siguen el mismo formato que la dirección de correo electrónico, lo que significa que tenemos 3 posibles usuarios:
  • martín
  • hadi
  • jimmy
Descargaré la clave privada usando wget, la canalizaré a través de algunos comandos para omitir la primera y la última línea del archivo (están en blanco), cambiaré los permisos del archivo SSH y finalmente usaré para intentar inicie sesión con los tres usuarios para ver quién trabaja.

#wget -qO - http://192.168.161.49/icons/VDSoyuAXiO.txt | tail -n +2 | head -n -1 > key.pem 


¡Bien, así que estoy como Martin! Probé con hadi y jimmy también, pero ambos me pidieron una contraseña, por lo que la clave no les pertenecía.

La solicitud de la contraseña para acceder al laboratorio secreto es un poco extraña, y supuse que la contraseña era PASSWORD. 


Bueno capturamos la primera bandera en el usuario martin.

Buscando a través de los archivos, echamos un vistazo a cron job.

# cat /etc/crontab


Encontramos que un archivo llamado sekurity.py en / tmp / debe ejecutarse cada 5 minutos. Pero el archivo falta en la carpeta. Así que creamos nuestro propio shell inverso y lo guardamos como sekurity.py en la carpeta / tmp /

#nano sekurity.py 

Introducimos ese código donde se encuentra nuestra dirección IP de la maquina y el puerto de escucha. Lo puedes encontrar en este link.

https://www.semecayounexploit.com/?sec=python&nota=19

http://pentestmonkey.net/cheat-sheet/shells/reverse-shell-cheat-sheet




 


IMPORTANTE..!!!!!

Antes de ejecutar la shell en python vamos a abrir un puerto de escucha



Como observamos después de 5 min se ejecuto el archivo dentro de /tmp/ . 
Una vez que se ejecuta el archivo, obtenemos nuestro shell inverso como un usuario diferente.


Genial, hemos iniciado sesión como jimmy y hay un archivo llamado networker que es propiedad de root y también tiene el bit SUID configurado. Probablemente ese sea nuestro boleto para aumentar nuestros privilegios.

Bueno luego de intentar jugar con ello , me doy cuenta que el binario networker es una mentira. No hay nada en él que sea útil. No toma ninguna entrada, no abre ningún puerto y las rutas están codificadas de forma rígida. 

En busca de obtener el modo root ....

Luego de analizar el directorio / home / hadi tenía algunas otras entradas, pero nada de valor. Una cosa que me llamó la atención fue el hecho de que el archivo / home / hadi / gdb_history era propiedad de root, así que sospecho que podemos usar hadi para llegar a root.



Voy a proceder a crear mi diccionario para fuerza bruta , existen muchos métodos para hacerlo o fácilmente probar con algunos diccionarios que nos proporciona kali linux ya depende de uno como lo quiera realizar.

Después de crear un diccionario, usamos metasploit para abrirnos paso a fuerza bruta en ssh.









Ahora, una vez que ingresamos al shell, generamos el terminal y usamos la contraseña de hadi ('hadi123') para ingresar al shell root.


Por fin.. obtenemos el acceso root y procederemos a buscar la bandera.

Se me olvidaba otra forma de obtener las credenciales mediante fuerza bruta para obtener acceso de la cuenta es mediante hydra. claro esta que debemos de tener nuestro diccionario.


Bueno acá les dejo la captura de la bandera
