01. ¿Qué es PVGUARD Checker Clickjacking?

PVGUARD Checker Clickjacking es una herramienta en Python diseñada para comprobar si una aplicación web puede ser cargada dentro de un iframe sin restricciones adecuadas.

Su objetivo es ayudar a pentesters, auditores y equipos DevSecOps a validar controles de seguridad contra Clickjacking, generar evidencia visual y documentar hallazgos de forma clara dentro de reportes profesionales.

🖼️

Prueba de iframe

Verifica si una URL objetivo puede ser embebida dentro de un iframe.

🛡️

Validación de Headers

Evalúa X-Frame-Options y CSP frame-ancestors como controles principales.

📄

PoC HTML

Genera una prueba visual para evidenciar el comportamiento de la aplicación.

🎭

Templates

Incluye plantillas para demostraciones controladas en laboratorios autorizados.

⚙️

Uso por CLI

Permite ejecutar análisis rápidos desde terminal con parámetros simples.

💀

Estilo Pentesting

Diseñada para auditorías web, Bug Bounty y generación de evidencia técnica.

05. Uso general

Puedes analizar una URL objetivo, generar una PoC HTML, guardar el resultado con un nombre personalizado o validar únicamente los headers defensivos.

Analizar una URL y generar PoC
./checker_clickjacking -u https://example.com
Guardar el resultado con nombre personalizado
./checker_clickjacking -u https://example.com -o reporte_clickjacking.html
Usar una plantilla específica
./checker_clickjacking -u https://example.com --template banca
Controlar opacidad del iframe víctima
./checker_clickjacking -u https://example.com --template alerta --opacity 0.5
No abrir automáticamente el navegador
./checker_clickjacking -u https://example.com --no-open
Verificar solo headers sin generar PoC
./checker_clickjacking -u https://example.com --check-only
Generar PoC sin validar headers
./checker_clickjacking -u https://example.com --no-check

08. Headers evaluados

La herramienta revisa principalmente controles que impiden o restringen que una aplicación sea cargada dentro de un iframe por sitios externos.

Header Objetivo Valor recomendado
X-Frame-Options Define si el sitio puede ser cargado dentro de un iframe. DENY o SAMEORIGIN
Content-Security-Policy Control moderno para restringir qué orígenes pueden embeber el sitio. frame-ancestors 'none' o frame-ancestors 'self'
Bloqueo total recomendado
X-Frame-Options: DENY
Content-Security-Policy: frame-ancestors 'none';
Permitir solo mismo origen
X-Frame-Options: SAMEORIGIN
Content-Security-Policy: frame-ancestors 'self';
Permitir dominio autorizado específico
Content-Security-Policy: frame-ancestors 'self' https://dominio-autorizado.com;

09. Interpretación de resultados

La ausencia de controles anti-iframe puede permitir que una página sea embebida dentro de otra interfaz, facilitando ataques de engaño visual si no existen medidas compensatorias.

Estado Significado Ejemplo
OK Existe una protección adecuada contra iframe. X-Frame-Options: DENY
WARNING Existe una política, pero debe revisarse su alcance. frame-ancestors con dominios demasiado amplios.
HIGH No se identifican controles anti-iframe efectivos. Ausencia de X-Frame-Options y frame-ancestors.
INFO Resultado informativo dependiente del contexto de la aplicación. Aplicación que requiere iframe por una integración legítima.
Importante: si una aplicación necesita ser embebida por terceros, la política debe ser explícita, restrictiva y limitada únicamente a dominios autorizados.

10. Recomendaciones de remediación

Para mitigar Clickjacking, se recomienda implementar controles a nivel de cabeceras HTTP y validar que los navegadores modernos apliquen correctamente la restricción.

🛡️

X-Frame-Options

Configurar DENY para bloqueo total o SAMEORIGIN si solo se permite el mismo origen.

🧱

CSP frame-ancestors

Usar frame-ancestors como control moderno para restringir dominios autorizados.

🔍

Validación continua

Revisar los headers después de cambios en servidores, balanceadores, CDN o WAF.

🌐

Dominios permitidos

Evitar políticas amplias y permitir únicamente dominios realmente necesarios.

📄

Evidencia técnica

Adjuntar capturas, PoC HTML y salida de headers dentro del reporte de seguridad.

⚙️

Hardening web

Combinar esta protección con CSP robusta, cookies seguras y validación de sesiones.
