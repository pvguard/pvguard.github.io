01. ¿Qué es PVGUARD Security Headers Checker?

PVGUARD Security Headers Checker es una herramienta enfocada en la revisión técnica de cabeceras HTTP de seguridad. Su objetivo es identificar headers ausentes, configuraciones débiles, políticas demasiado permisivas y exposición innecesaria de información del servidor.

Es útil durante pruebas de penetración web, auditorías de hardening, validaciones DevSecOps, revisiones de cumplimiento y generación de evidencia para reportes técnicos.

🛡️

Validación de Headers

Evalúa cabeceras como HSTS, CSP, X-Frame-Options, Referrer-Policy, Permissions-Policy y más.

📄

Reporte HTML

Permite generar evidencia visual para adjuntar en informes técnicos de auditoría.

🧪

Pruebas Autenticadas

Soporta cookies, tokens Bearer y cabeceras personalizadas para evaluar rutas protegidas.

⚙️

Uso por CLI

Ejecuta análisis rápidos desde terminal con parámetros simples y salida clara.

🔎

Modo Proxy

Puede trabajar junto con Burp Suite, OWASP ZAP o mitmproxy para conservar evidencia.

💀

Estilo Pentesting

Diseñada para laboratorios, auditorías autorizadas y validaciones de seguridad web.

07. Cabeceras evaluadas

La herramienta permite revisar cabeceras críticas para endurecimiento web y controles defensivos del navegador. Estas cabeceras ayudan a reducir riesgos como Clickjacking, MIME Sniffing, downgrade HTTPS, exposición de información, abuso de APIs del navegador y políticas CORS inseguras.

Header Riesgo asociado Valor recomendado
Strict-Transport-Security Downgrade HTTPS / SSL Stripping max-age=31536000; includeSubDomains
Content-Security-Policy XSS, carga de recursos no confiables y Clickjacking Política restrictiva sin unsafe-inline ni unsafe-eval
X-Frame-Options Clickjacking DENY o SAMEORIGIN
X-Content-Type-Options MIME Sniffing nosniff
Referrer-Policy Exposición de rutas, tokens o parámetros sensibles strict-origin-when-cross-origin
Permissions-Policy Uso no controlado de cámara, micrófono, geolocalización y APIs del navegador Restringir permisos innecesarios
Access-Control-Allow-Origin CORS permisivo Evitar * cuando existan credenciales
Server / X-Powered-By Divulgación de tecnología o versiones Reducir o eliminar información innecesaria

08. Interpretación de resultados

Los resultados deben interpretarse según el contexto de la aplicación, exposición pública, criticidad del activo y controles compensatorios existentes.

Estado Significado Ejemplo
OK La cabecera existe y tiene una configuración aceptable. X-Content-Type-Options: nosniff
HIGH Falta una cabecera crítica o existe una configuración de alto riesgo. Ausencia de HSTS en aplicación HTTPS.
WARNING La cabecera existe, pero requiere endurecimiento. CSP con unsafe-inline o unsafe-eval.
INFO Hallazgo informativo o dependiente del contexto. Divulgación de servidor mediante Server.
Importante: una cabecera ausente no siempre significa explotación directa, pero sí representa una debilidad de hardening que debe ser evaluada y priorizada.

09. Recomendaciones de hardening

Las siguientes configuraciones ayudan a reducir riesgos comunes relacionados con seguridad del navegador, exposición de información y abuso de políticas permisivas.

🔐

HSTS

Configurar Strict-Transport-Security para forzar HTTPS y reducir riesgos de downgrade.

🧱

CSP

Implementar Content-Security-Policy evitando unsafe-inline, unsafe-eval y orígenes amplios.

🖼️

Clickjacking

Usar X-Frame-Options o CSP frame-ancestors para controlar carga dentro de iframes.

🧬

MIME Sniffing

Mantener X-Content-Type-Options con valor nosniff.

🌐

CORS

Evitar Access-Control-Allow-Origin abierto cuando existan credenciales o datos sensibles.

🕵️

Divulgación

Reducir información expuesta en Server, X-Powered-By y cabeceras con versiones internas.
